# Day36

## 実施内容

- MISRA 12.1（演算子優先順位の明示）を`diag.c`・`ignition.c`・`validate.c`（計4箇所）に適用
- MISRA 18.4（ポインタ演算）を`cmd.c`（1箇所、`line + 6`→`&line[6]`）に適用
- MISRA 21.6/21.10（標準入出力・time.h使用制限）・15.5（単一出口）は不採用と判断

## 確認内容

- `make clean && make`で警告なしにビルドできること
- `make test`で全9ターゲット・51テスト関数がPASSすること
- cppcheck（`--addon=misra`）を再実行し、12.1・18.4の指摘が0件になること
- `make run`で通常動作（`clear`コマンド含む）が従来通りであること

## 実行結果

- `make`：成功、警告・エラーなし
- `make test`：9ターゲット全部ビルド成功、51テスト関数、0 Failures
- cppcheck再実行：12.1・18.4は0件。21.6/21.10（13件）・15.5（41件）は意図した不採用のまま継続
- `make run`：終了コード0、`clear`コマンド受付・DTC保存まで正常動作

## 判定

成功。12.1・18.4は適用し、動作・出力を変えずに解消した。21.6/21.10・15.5は不採用と判断し、理由をREADME.md・project_context.md・study_plan.mdに一貫して記録した。これでPhase14の12ルール全てに採否の決着がつき、Phase14を完了とした。

## 今回の設計方針

- 21.6/21.10（標準入出力・time.h制限）を不採用とした理由：このプロジェクトはPC上のシミュレータであり、`printf`/`fopen`/`time`を使うこと自体が設計前提。将来Renode等でtarget向け実装を作る段階になれば、`logger.c`/`persist.c`等の入出力担当モジュールを差し替える形で対応すべき話であり、今のPC版コードから標準ライブラリを排除することとは別の話だと整理した
- 15.5（単一出口）を不採用とした理由：MISRA C:2012での分類はAdvisory（プロジェクトの裁量）であり、ガード節（早期return）による可読性重視の設計と衝突する。単一出口化には41箇所でのフラグ変数導入が伴い、CLAUDE.mdが避けたい大規模リファクタリングに該当すると判断した
