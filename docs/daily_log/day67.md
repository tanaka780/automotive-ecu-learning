# Day67

## 実施内容

- 再生画面に、異常が無いときの「正常な運転」の場面を足し、開いたときに最初に出るようにした
- 再生画面の主な場面を、正常な運転・冷却ファン・温度センサーの異常・オーバーヒート・通信の途切れ・整備工場での点検の6つにした（整備工場での点検を、そのほかの場面から移した）

## 確認内容

- 正常な運転の場面で、警告・異常・ファンONがどの秒にも出ず、記録が残らないか
- 場面ごとの期待と、本体の出力から作った画面の情報が食い違っていないか。足した場面のほかは、データが変わっていないか
- PCの幅では主な場面が3列×2段に並び、スマホの幅（375px）では、どの場面でも横にはみ出さないか
- READMEの冒頭の画像を、READMEに書いた手順で撮り直せるか

## 実行結果

| 確認 | 結果 |
| --- | --- |
| `tools/make_viewer_data.py` | 20場面・83項目、食い違いなし |
| 正常な運転の中身 | 出来事は1秒目の「エンジンをかけた」だけ。メーターは20秒とも50km/h・2000・70℃、ファンは一度も回らない。起動時の自己点検は合格、終了時の記録は4つとも「記録なし」 |
| 別の読み方での照らし合わせ | 食い違い0件 |
| Day66のコミットとの比べ（場面の名前で突き合わせ） | ほかの18場面はまったく同じ。整備工場での点検は、分類（そのほか→主な場面）とひとこと説明が変わっただけ |
| 主な場面の並び | 正常な運転 → 冷却ファン → 温度センサーの異常 → オーバーヒート → 通信の途切れ → 整備工場での点検。開いたときは正常な運転。そのほかの場面は14件 |
| PCの幅（1000px） | 3列×2段に並ぶ |
| スマホの幅（375px） | 20場面の1〜20秒目をすべて（400画面）表示して測り、どれも横にはみ出さない |
| READMEの冒頭の画像 | ボタンの並びが変わったので撮り直した。READMEに書いた手順（場面の番号を3から4に直した）で撮ると、差し替えた画像と同じ |

スマホの幅は、最初に画面なしのEdgeで撮った画像では右側が切れて見えた。Edgeが一定より狭い幅の画面を作れないためと考えている（確かめてはいない）。ブラウザの表示幅を375pxにして測り直した。

## 判定

再生画面を開くと、異常が無いときの普段の動きから見始め、主な場面の6つで、普段の動き・異常・記録と点検を順にたどれるようになった。

- 正常な運転の場面は、期待（何も起きないこと）と出力が一致した
- 場面の追加と並びの変更で、ほかの場面の情報は変わらず、照らし合わせも食い違いが無かった
- PCとスマホのどちらの幅でも、表示が崩れなかった

## 今回の設計方針

- 新しく作る場面は正常な運転だけにし、ほかは今ある場面を使った
- 段階A・B（かけ直し）やPhase29（通信の途切れの記録）の場面は、最初の説明には細かいので足さなかった
- 正常な運転の期待には、出てはいけない出来事（警告・異常・ファンON）も書いた。何も起きないことを見せる場面なので、出来事が出ることだけを期待にすると、誤って警告が出ても気づけない
