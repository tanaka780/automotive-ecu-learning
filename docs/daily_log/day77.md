# Day77

## 実施内容

- 再生画面に、ファン係の処理が止まっても安全のためファンを回し、処理が動き出したら元の判断に戻る場面を足した。止まっている間の字幕が「すべて正常」にならないようにした
- pushとプルリクエストのたびに、ビルド（依存の向き・警告0件）・単体テスト・シナリオ検証と、再生画面のデータが今のコードと合っているかを自動で確かめる仕組み（GitHub Actions）を用意した
- その手順を、新しく取り出した状態のフォルダで動かして確かめた

## 確認内容

- 再生画面の新しい場面で、試験台が処理を止めた秒・ファン係が止まったと判断してファンを回した秒・処理が動き出した秒・ファンを止めた秒が、期待どおりに出るか。前からある20場面のデータが変わらないか
- 処理が止まっている間の字幕が、「すべて正常」にならないか
- 新しく取り出した状態のフォルダで、GitHub Actionsの手順がすべて通るか。警告が出たときに、ビルドの段階で失敗するか
- 再生画面のデータがコードと合っていないときに、4つ目の段階で失敗するか
- 計算機が忙しく時間が揺れやすいときも、実時間の版を含むシナリオ検証が通るか

## 実行結果

再生画面（「ファン係の処理が止まる」の場面。温度を70℃→6秒目100℃→16秒目80℃、2〜12秒の間に回すかを決める処理を止める）

| 確認 | 結果 |
| --- | --- |
| `tools/make_viewer_data.py` | 21場面を書いた。期待との照らし合わせ88項目、食い違いなし |
| 前からある20場面のデータ（足す前と後） | 20場面とも一致 |
| 新しい場面の秒ごとの出来事 | 3秒目に「（試験）…処理が止まった」、4秒目に「処理が止まっていると判断」と「安全のためファンを回し始めた」、13秒目に「処理が動き出した」「判断が再開した」（ファンは100℃なので回したまま）、16秒目に「ファンを止めた」 |
| ブラウザで開いて5秒目（出来事の無い秒）の字幕 | 直す前は「すべて正常に動いています」と「ファンを回しています（理由：ファン係の処理が止まっている）」が並んだ。直した後は「ファン係：処理が止まっていると判断しています」と理由の文になった。コンソールのエラーは0件 |

GitHub Actions（`.github/workflows/ci.yml`の各段階の`run`を、新しく取り出した状態のフォルダで、GitHubと同じ`bash -eo pipefail`で動かした）

| 確認 | 結果 |
| --- | --- |
| 最初の書き方（`grep -i "warning"`で警告を探す） | 単体テストの段階が失敗した。`test_active_to_history_via_warning`などのテストの名前に当たったため |
| `": warning:"`を探すように直した後、わざと警告が出るコードを`logger.c`に足す | ビルドの段階で`warning: unused variable`などを見つけ、「ビルドで警告が出た」で失敗した |
| 直した後、そのまま | 4段階とも通った（ビルド・単体テスト222件・シナリオ検証106件・再生画面のデータに差が無い）。約2分半 |
| コミットした再生画面のデータの1か所（正常な運転の1秒目の出来事）をわざと書き換えて、4つ目の段階を動かす | `viewer/index.html`の差が見つかり、終了コード1で失敗した。作り直したデータをコミットし直すと、終了コード0で通った |
| 計算機を忙しくした状態（WSLのCPU16個すべてで、重い処理を後ろで動かし続ける）で`make scenario` | 106件すべてOK（約136秒）。忙しくしないときと同じ時間で、実時間の版の条件も落ちなかった |

## 判定

- 再生画面の新しい場面は、期待した秒に期待した出来事が出て、前からある20場面は変わらなかった。期待通り
- 字幕は、出来事の無い秒に「今の状態」を文にする作りで、ファン係が処理の停止を見つけている状態を知らなかったため、「すべて正常」と出ていた。ブラウザで実際に開いて初めて分かった（データの照らし合わせは出来事の文しか見ていない）
- GitHub Actionsは、最初の書き方のままGitHubに置いていたら、正しいコードでも毎回失敗していた。手元で同じ手順を動かして見つけた。直した後は、警告を入れると失敗し、入れなければ通ることの両方を確かめた
- 再生画面のデータがコードと合っていないときは失敗し、合っていれば通った。4つ目の段階は、作り直し忘れを見つけられる
- 忙しくした計算機でもシナリオ検証は落ちなかったので、時間の揺れには一定の余裕がある。ただし、GitHubの計算機（CPUの数や速さ）とは条件が違うので、目安にとどまる
- GitHubの上で実際に動くかは、pushしてみるまで分からない

## 今回の設計方針

- 再生画面の新しい場面は、回すかを決める処理を止め、止めている間に温度が100℃に上がる筋書きにする（止まったままなら熱くなってもファンが回らない危険を、場面の説明で伝えられるため）
- 新しい場面は「そのほかの場面」に入れる（主な場面は3列×2段で並べているため）
- GitHub Actionsは、手元の確かめ（ビルド・警告0件・`make test`・`make scenario`）と、再生画面のデータが今のコードと合っているかを動かす
- 警告は、gccの出す形の`": warning:"`で探す。`warning`だけで探すと、テストの名前に当たって正しいコードでも失敗するため
