# Day48

## 実施内容

- 17テストターゲットそれぞれについて、担当モジュール1つのgcovカバレッジ結果を一括確認できる手段を用意した

## 確認内容

- 既存の`make clean && make`・`make test`が、カバレッジ機構の追加によって影響を受けないか
- 新規のカバレッジ確認手段が17ターゲットそれぞれをビルド・実行し、担当モジュール1つずつのgcov結果（実行行数の割合）を表示できるか

## 実行結果

| コマンド | 結果 |
| --- | --- |
| `make clean && make` | 警告0件 |
| `make test` | 既存17ターゲット全てPASS（検証内容の変更なし） |
| `make coverage` | 17ターゲット全てビルド成功。担当モジュールの実行率は`test_validate`100%〜`test_diag`34.33%まで分布（表示専用関数`diag_print`等が対象外な点は既存のテスト方針と整合） |

## 判定

期待通り。既存のビルド・テストへの影響は無く、新規のカバレッジ確認手段が意図通り動作した。

## 今回の設計方針

- `test_debounce`と`test_can`（同じ`debounce.c`を含む）を別々にビルド・実行し、gcovの実行回数が合算されるかを確認したところ、加算されないことが分かった（別ターゲットとして再ビルドすると`-o`名に紐づく`.gcno`のファイル名が変わるため）
