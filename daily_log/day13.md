# Day13

## 実施内容

- イグニッション状態管理を独立モジュール（ignition.h / ignition.c）として新規実装
  - `IgnitionState`（OFF/ON）を`Ignition`構造体（current/previous）で保持
  - 状態更新にはsensor.cのランダム更新パターン、遷移検出にはdiag.cの前回/今回比較によるエッジ検出パターンをそのまま流用、毎サンプルの状態表示と遷移した瞬間だけのイベント表示を実装

## 確認・検証

| 確認観点 | 結果 |
| --- | --- |
| ビルド（-Wall -Wextra -std=c11） | 警告・エラーなし。ビルド成功 |
| テストビルド（make test） | 31 passed, 0 failed |
| 実行確認（make run） | OFF中は`[IGN] OFF`のみ表示され、sensor/status/alert/diag/statsの行が出力されないことを確認。ON中はこれまで通り全項目が出力される。遷移した瞬間のみ`[IGN] OFF -> ON`等が表示される。統計は実行中にONだったサンプル数（今回は10）だけで平均が計算されている |

## 今回の設計方針

- 既存パターンの流用：新しいロジックパターンを増やさず、状態更新はsensor.cのランダム更新パターン、遷移検出はdiag.cの前回/今回比較によるエッジ検出パターンをそのまま使う設計にした
- 表示形式：status.cと同じ考え方で、状態表示・遷移イベントの両方をタグ付き（`[IGN]`）にした。
- OFF中の連携方針を決定：`sensor_update`/`status_check`/`diag_check`/`alert_check`/`stats_update`を全てスキップする（main.cで`if (ignition.current == IGNITION_ON)`のブロックにまとめて実装）
- サイクルをまたいだとき（OFF→ON→OFF等）のDTC・統計の扱いを決定：どちらもリセットせず通算で継続する（コード変更なし。元々サイクルをまたいでも状態を保持する実装だったため）
